设计结论：**有条件接受，可按下列边界实施；尚未审阅或批准生产代码。** 源提交 `ecee0961f16f59d568f18aabe33b55ec49620b33`，本轮只读F。

显式schemaVersion2、共享字符串/键字典与number/array/object标签有充分区分度；新增literal字符串/键分支可减少无收益字典项，且不要求改PCR语义、路由或浏览器压缩依赖。保留schema1及unkeyed读取，符合现有Inspector和导出验证入口。

必须落实：

- **R1** Validate and charge the whole encoded pack in a non-materializing first pass, then materialize only the selected record or validated complete pack. No decoded object/array tree, spread, flatMap or expanded JSON.stringify before the shared restored-byte guard passes.
- **R2** Restored size means exact UTF8 JSON serialization of the canonical v1 envelope (including all rows, record keys, brackets, commas, object key quotes/escapes, colons and wrapper fields). Dictionary costs cache UTF8(JSON.stringify(string)); charge each occurrence, not each unique string. Null/booleans/finite numbers use their exact JSON rendering; reject as soon as charged bytes >=25000000. Use safe, saturating arithmetic.
- **R3** Writer must measure candidate restored bytes before calling a strict encoder that can throw for expansion. If pending exists and candidate physical>1000000 OR restored>=25000000 OR count>32, flush pending then recompute the singleton. Do not swallow malformed-input failures as capacity splits. Never emit a selected encoding that its public decoder rejects; one oversized physical record retains existing <25MB physical requirement and stays whole.
- **R4** Grammar: null/boolean/literal-string pass as values; bare numbers are only safe integer refs0<=id<dictionary.length; actual number token is exactly[0,finite-number]; array is[1,...encoded-values]; object is[2,(literal-string|reference),encoded-value,...] with odd length. Reject unknown tags, wrong arity, raw objects, undefined, NaN/Infinity, float/negative/out-of-range refs, missing values, mixed token kinds and unsupported versions. Decoded manifest/structured roots must be objects, not arrays/scalars.
- **R5** Dictionary strings and record keys are distinct; record keys nonempty, max32. Object keys are decoded then checked by Set<string>, covering mixed literal/ref collisions. Materialize with Object.fromEntries or Object.defineProperty own enumerable data properties, never target[key]=value on ordinary {} for __proto__. Test __proto__,constructor,prototype,toString,empty keys,numeric-like keys,Unicode and nested objects; preserve native Object.entries/JSON.stringify ordering.
- **R6** Set an explicit shared nesting bound and check it before recursive descent in encoder/preflight/materializer. Confirm every actual current/history record is below it, and test exactly-at/one-past with controlled errors instead of RangeError. Iterative preflight is also acceptable. Physical JSON parsing already occurs before decode; this guard limits decoded expansion, not all response.json memory.
- **R7** Frequency/first-appearance/ID pruning must be deterministic. Count both key and value occurrences, including literal-escaping UTF8 bytes and decimal reference widths/dictionary framing. Two rounds may be a conservative heuristic, not a global optimality claim. Final v1/v2 selection compares complete actual UTF8 serialized bytes, with v1 on ties. Validate v1 first and preserve its bytes for nonbeneficial cases.
- **R8** Retain unkeyed and schema1 reads and exact missing-key/unknown-version/retry behavior. New artifacts ship their decoder. Old decoder accepting new schema2 is not promised; historical bytes/readers remain unchanged. Verify all1600 actual records through unchanged public decode entrypoint with exact serialized record identity, and run shipped-export comparison plus Root fresh full validation/docs build.

关键反例：32条记录各包含同一900,000-byteASCII字符串，方案的紧凑包约900686bytes，满足1MB物理target；完整恢复v1包为28800757bytes，超过25MB。必须预先按每次引用出现计费，并在writer编码候选可能抛错前flush/recompute；此为纯数学设计示例，不是工厂数据。

独立证据：实际读回全部1600条当前/历史生成record的原始字节，逐一SHA与Root保留probe一致；实际最大JSON值深度11。这只验证传输输入绑定，未重跑Root编码原型，也未完成新的public decode roundtrip或浏览器测试。Root原型108包/预计19999文件只能作为初步可行性；原型UTF16选择比较及新增literal分支需按实际UTF8重测。

没有独立测量证明更小替代方案足够。建议保留这个通用、小范围codec，并以上述严格预校验/计费、全1600 publicdecode逐字恢复、最终文件数、Root完整fresh validation/docs build作为实施验收。所有源SHA、具体grammar、费用定义与局限见design-review.json。
